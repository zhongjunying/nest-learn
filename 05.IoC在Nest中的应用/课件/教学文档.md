## IoC与依赖注入的基本概念

IoC（Inversion of Control，控制反转）是一种设计思想：**对象的创建和管理权交给容器**，开发者不再手动 new 对象，而是由容器自动注入依赖。Nest 内部维护了一个 IoC 容器，负责管理所有被标记的组件（控制器、服务、提供者等）的生命周期和依赖关系。

在 Nest 中，要让一个类被 IoC 容器管理，需要用到两个关键装饰器：

- **`@Controller()`** — 标记该类是一个控制器，控制器专门处理 HTTP 请求，**只作为"消费者"使用**，一般不作为依赖被注入到其他类中。
- **`@Injectable()`** — 标记该类是一个提供者（可被注入的组件），比如 Service、Filter（过滤器）、Interceptor（拦截器）、Guard（守卫）、Gateway（网关）等。只要是需要被 IoC 容器收集和注入的类，都可以用 `@Injectable()` 标记。

最后，还需要在模块中将这些组件声明到 `controllers` 和 `providers` 数组中，Nest 的 IoC 容器才能够识别和管理它们。

## 控制器的注入方式

在 [app.controller.ts](代码/cli-test/src/app.controller.ts) 中可以看到典型的控制器注入写法：

```typescript
@Controller('app')
export class AppController {
  constructor(private readonly appService: AppService) {}
}
```

控制器类通过 `@Controller('app')` 装饰器标记，路由前缀为 `app`。构造器的参数 `private readonly appService: AppService` 告诉 Nest：这个控制器依赖 `AppService` 实例。Nest 的 IoC 容器在实例化 `AppController` 时，会自动将 `AppService` 的实例传进来。

这个过程不需要开发者手动 `new AppService()`，完全由容器处理。

## 提供者（Provider）的注册

在模块中声明提供者，Nest 才知道哪些类可供注入。`@Module` 装饰器的 `providers` 数组就是做这件事的。

在 [app.module.ts](代码/cli-test/src/app.module.ts) 中：

```typescript
@Module({
  imports: [UserModule, PersonModule],
  controllers: [AppController],
  providers: [
    {
      provide: AppService,
      useClass: AppService,
    },
  ],
})
export class AppModule {}
```

这种 `{ provide: AppService, useClass: AppService }` 的写法是完整写法。其中：

- **`provide`**：指定注入的 Token（标识符），IoC 容器通过 Token 来唯一识别一个提供者。
- **`useClass`**：指定提供者的类，Nest 会自动实例化这个类并将实例注册到容器中。

当 `provide` 的值和 `useClass` 的值相同时，可以简写为 `providers: [AppService]`。

## 字符串 Token 注入

Token 不一定是类，也可以是字符串。用字符串做 Token 可以更灵活地命名提供者。

在 [user.module.ts](代码/cli-test/src/user/user.module.ts) 中：

```typescript
@Module({
  controllers: [UserController],
  providers: [
    {
      provide: 'user_service',
      useClass: UserService,
    },
  ],
})
export class UserModule {}
```

这里的 Token 是字符串 `'user_service'`，而不是 `UserService` 类。由于 Token 不再是类，注入时必须配合 `@Inject()` 装饰器来指定 Token。

在 [user.controller.ts](代码/cli-test/src/user/user.controller.ts) 中：

```typescript
@Controller('user')
export class UserController {
  @Inject('user_service')
  private userService: UserService;

  @Get('list')
  getUserList() {
    return this.userService.getUserList();
  }
}
```

当访问 `GET /user/list` 时，返回用户列表数据：

```json
[
  { "id": 1, "name": "jack", "age": 19 },
  { "id": 2, "name": "rose", "age": 17 }
]
```

## 属性注入（Property Injection）

除了通过构造器注入，Nest 还支持通过属性装饰器 `@Inject()` 直接注入到类的属性上。这种方式不需要写构造器。

用 `@Controller('app')` 下的写法对比：

**方式一：构造器注入（Token 为类，无需 @Inject）**

```typescript
constructor(private readonly appService: AppService) {}
```

**方式二：属性注入**

```typescript
@Inject(AppService)
private appService: AppService;
```

两种写法效果相同，属性注入更简洁一些。当 Token 是字符串时，无论构造器还是属性注入都需要 `@Inject()`。

构造器注入配合字符串 Token 的写法：

```typescript
constructor(@Inject('app_service') private readonly appService: AppService) {}
```

## Provider 直接注入值（useValue）

Provider 不仅可以注入一个类的实例，也可以直接注入一个字面量值（对象、字符串、数字等）。通过 `useValue` 实现。

在 [app.module.ts](代码/cli-test/src/app.module.ts) 中注册了一个 car 对象：

```typescript
{
  provide: 'car',
  useValue: {
    brand: 'BYD',
    price: 100000,
  },
},
```

在 [app.controller.ts](代码/cli-test/src/app.controller.ts) 中注入并使用：

```typescript
@Inject('car')
private car: { brand: string; price: number };

@Get('hello1')
getHello1(): string {
  return (
    this.appService.getHello() +
    '---' +
    this.car.brand +
    '---' +
    this.car.price +
    '---' +
    this.random
  );
}
```

访问 `GET /app/hello1`，返回结果类似：

```
Hello World!---BYD---100000---0.123456789
```

这里 `car` 不是一个类的实例，而是一个普通的 JavaScript 对象，包含了品牌和价格信息。`useValue` 非常适合注入配置信息、常量等。

## Provider 动态注入值（useFactory）

有些值需要在运行时动态计算，或者需要依赖其他提供者的值。`useFactory` 支持通过工厂函数来创建值，并且可以通过 `inject` 注入其他已注册的提供者。

在 [app.module.ts](代码/cli-test/src/app.module.ts) 中，`random` 这个提供者使用了工厂函数：

```typescript
const createRandomFactory = (
  car: { brand: string; price: number },
  appService: AppService,
) => {
  return {
    random: Math.random(),
    brand: car.brand,
    hello: appService.getHello(),
  };
};

@Module({
  // ...
  providers: [
    {
      provide: AppService,
      useClass: AppService,
    },
    {
      provide: 'car',
      useValue: { brand: 'BYD', price: 100000 },
    },
    {
      provide: 'random',
      useFactory: createRandomFactory,
      inject: ['car', AppService],
    },
  ],
})
export class AppModule {}
```

关键点：

- **`useFactory`**：指向一个工厂函数，Nest 在应用启动时会调用这个函数，返回值将作为该提供者的值。
- **`inject`**：数组，指定工厂函数的参数来源。Nest 会根据数组中的 Token（这里分别是 `'car'` 和 `AppService`）从 IoC 容器中取出对应的实例，传入工厂函数。

`createRandomFactory` 函数接收两个参数：`car` 对象和 `appService` 实例，组合成一个新的对象返回。这样就实现了多个提供者之间的组合。

在 [app.controller.ts](代码/cli-test/src/app.controller.ts) 中注入 `random`：

```typescript
@Inject('random')
private random: number;

@Get('random')
getRandom() {
  return this.random;
}
```

访问 `GET /app/random`，返回类似：

```json
{
  "random": 0.123456789,
  "brand": "BYD",
  "hello": "Hello World!"
}
```

这个值在应用启动时由工厂函数生成一次，此后在整个应用生命周期中保持不变。工厂函数的参数来自容器中已注册的 `'car'` 和 `AppService`，这种能力让 Provider 之间可以灵活组合。
